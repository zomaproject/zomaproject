## Sobre mí

Construyo aplicaciones web completas: APIs en **.NET 10** con Minimal APIs, SPAs en **React 19 + TypeScript** e infraestructura **serverless en AWS** definida con **Terraform**.

## Cómo trabajo

- 📏 **La arquitectura se ajusta al tamaño del proyecto.** Un CRUD es un solo proyecto con Vertical Slice; las capas y CQRS llegan cuando el negocio las pide, no antes.
- 📜 **El contrato es OpenAPI.** El backend lo publica y el frontend genera sus tipos con `openapi-typescript`. Ningún tipo de API se escribe dos veces.
- 🧪 **Pruebas contra infraestructura real.** Integración con `WebApplicationFactory` sobre bases de datos en Docker, no mocks del `DbContext`.
- ☁️ **Infraestructura como código.** Todo lo de AWS vive en Terraform con state remoto en S3; nada se crea a mano en la consola.
- ✂️ **Sin sobreingeniería.** Nada de repositorios genéricos, MediatR ni AutoMapper si no resuelven un problema real.

## Proyecto actual: Habit Tracker

Aplicación personal para llevar **finanzas** y **entrenamiento en el gimnasio**, 100 % serverless en AWS.

- 💰 **Dinero:** cuentas, categorías, movimientos recurrentes que se aplican solos y vista mensual con saldo actual y proyectado.
- 🏋️ **Entrenamiento:** catálogo de máquinas, rutinas de lunes a viernes generadas con IA (Amazon Bedrock), registro por serie con sugerencia de peso por doble progresión, rachas y peso corporal.

```mermaid
flowchart TB
    U[Navegador] --> CF[CloudFront + S3<br/>SPA React 19]
    U -->|JWT| GW[API Gateway<br/>autorizador Cognito]
    CF -.->|OIDC + PKCE| COG[Cognito]
    GW --> L[Lambda<br/>.NET 10 Minimal API]
    L --> DDB[(DynamoDB<br/>single table)]
    L --> BR[Bedrock<br/>rutinas con IA]
```

**Decisiones destacadas**

- **DynamoDB single-table** con `PK = USER#{id}`: cada pantalla es una sola `Query` sobre una partición.
- El saldo de cada cuenta se actualiza con `TransactWriteItems` en lugar de sumar movimientos en cada lectura.
- La IA responde mediante una *tool call* forzada que devuelve JSON, y un validador la contrasta con el catálogo antes de guardar.
- Desarrollo local con **DynamoDB Local en Docker**, que también usan las pruebas de integración.
